6. Did you design your app with a particular type of user in mind? If so, whom?

Yes, the app is designed for users who prefer simple apps rather than overly complicated ones. My app is easy to use and easy to read, and creating a log only takes a few clicks.



7. Did you design your app specifically for iOS or Android, or both?

More for iOS than Android. The app is combatible for both iOS and Android, but the formatting on iOS looks much better.



8. How can a person log overnight sleep in your app? Why did you choose to support logging overnight sleep in this way?

Click the "Log Overnight Sleep" button on the home page and enter a sleep and wake time. I wanted to make the logging process as simple as possible, so the popup that appears after clicking the button only takes two times (sleep and wake time) as input.



9. How can a person log sleepiness during the day in your app? Why did you choose to support logging sleepiness in this way?

Click the "Log Sleepiness" button on the home page and enter a sleepiness value and log time. I used a slider for the sleepiness value to represent the user's sleepiness as a meter, and once again, the log time is a simple time input.



10. How can a person view the data they logged in your app? Why did you choose to support viewing logged data in this way?

The logged data can be viewed at all times in the app's home screen. I thought it was redundant to have a separate button to view the logs, and having all the data right on the home page makes it extremely easy to find.



11. Which feature choose--using a native device resource, backing up logged data, or both?

Using a native device resource. 



12. If you used a native device resource, what feature did you add? How does this feature change the app's experience for a user?

Whenever the user inputs a strange value in a log (sleeping for over 16 hours or logging a sleepiness value in the future), the app gives an alert dialogue to ask the user if their input is truly correct. This adds a safeguard to the user experience and prevents them from unknowingly adding false data to their logs.



13. If you backed up logged data, where does it back up to?

No data is backed up.



14. How does your app implement or follow principles of good mobile design?

All buttons are the same color and shape to make them easily recognizeable as clickable objects. In addition, all input fields are formatted the same for consistency: a label above the input to denote what it is, a line for separation, and the input itself.
